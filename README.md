# melody_child

오늘 있었던 이야기를 말하면, 그 목소리를 음절 단위로 잘라 각 조각을 멜로디 음정으로 옮겨 동요를 만드는 정적 웹페이지.
목소리를 합성하지 않고 실제 녹음을 악기로 재사용한다. 외부 API·백엔드·의존성 없음.

8음 한 절을 만들고 음절 수만큼 절을 반복한다 — 동요가 원래 같은 곡조를 절마다 반복하는 구조라서,
이야기가 길어져도 곡이 산만해지지 않는다. 녹음은 30초까지.

## 실행

ES 모듈을 쓰기 때문에 `file://`로 열면 동작하지 않는다. 정적 서버로 띄운다.

```bash
python3 -m http.server 8000
```

- 앱: http://localhost:8000/
- 마이크 없이 파이프라인 확인: http://localhost:8000/index.html?dev=sample
- 음절 안에서 음높이가 흐르는 신호로 확인(실제 말소리에 가깝다): `?dev=glide`

### URL 손잡이

음정을 옮기는 폭이 곧 목소리 왜곡의 양이다. 귀로 비교할 수 있게 밖으로 뺐다.

| 파라미터 | 뜻 |
|---|---|
| `?mode=chant` | (기본) 목소리를 자르지 않고 멜로디를 아래에 깐다. 음절 시작만 격자에 맞춘다 |
| `?inst=orgel` | 멜로디 악기 기본값: `piano`(기본)·`orgel`·`marimba`·`synth`(예전 소리) — 결과 화면 버튼으로도 바꾼다 |
| `?align=0` | 정렬을 끄고 녹음을 통째로 흘려보낸다(박에 안 맞는 대신 완전히 자연스럽다) |
| `?mel=2.4` | 멜로디 음량 비율(정규화한 목소리 RMS 대비). 기본 2.4 — 결과 화면 버튼으로도 바꾼다 |
| `?tone=1` | 멜로디 배음 세기. 기본 1, `0`이면 순수 사인파, 올리면 밝고 크게 들린다 |
| `?ride=9` | 조용한 음절을 끌어올리는 상한(dB). 기본 9, `0`이면 완전히 끈다(라이드 이전과 비트 단위로 같은 소리). 멜로디 음량은 건드리지 않는다 |
| `?cover=0` | 조각 밖에 남은 조용한 발화를 재생 범위에 넣지 않는다(12차 이전 동작). 잡음이 붙을 때 원인이 이 확장인지 가르는 A/B — 단 말끝 뒤 250ms는 이걸 꺼도 재생된다 |
| `?mode=full` | 음절을 음정으로 옮겨 배치한다(5음계 전체) |
| `?mode=narrow` | 도·레·미 3음(4반음)으로 좁힌다 — 왜곡을 줄이고 곡조는 남긴다 |
| `?pad=1` | 멜로디 반주를 켠다(사인파·저역통과) — 챈트는 항상 켜져 있다 |
| `?debug=1` | 진단 숫자를 화면 칩으로 띄운다(폰에서는 콘솔을 볼 수 없다) |

챈트의 정렬은 **음절을 늘리거나 자르지 않는다.** 손대는 것은 음절 뒤의 쉼뿐이고
(쉼은 길이를 바꿔도 아티팩트가 없다), 격자는 박이 아니라 그 사람이 실제로 말한
음절 간격에서 고른다 — 4분음표 격자에 한 음절씩 놓으면 2.2초 발화가 3.75초로
늘어나 말이 다시 끊긴다(실측). 그래서 격자 후보를 120~200ms로 제한하고 긴 쉼은
격자 통계에서 뺀다(쉼은 배정 칸 수로 표현된다).

**음절 끝 80ms까지는 잘리게 둔다.** 자르지 않으려면 음절이 격자보다 조금만 길어도
배정 칸을 하나 더 줘야 하고, 재료가 없는 그 나머지가 전부 무음이 된다 — 실측 최대
256ms로 그게 "말이 뚝뚝 끊긴다"의 정체였다. 잘리는 곳은 감쇠부이고 뒤 조각과
크로스페이드로 이어지므로, 50ms 감쇠부가 사라지는 편이 256ms 무음보다 낫다.

조각 이음매는 **크로스페이드**로 잇는다. 뒤 조각이 바로 이어지는 자리에서는 앞
조각이 20ms 더 읽으며 내려가고 뒤 조각이 같은 시각에 올라와 진폭 합이 유지된다
(원본에서도 이어지면 같은 샘플을 읽어 파형이 원본과 같다). 뒤에 침묵이 있으면
더 읽지 않는다 — 그 20ms는 다음 음절의 머리라서, 더 읽으면 그 머리가 최대 250ms
앞당겨 한 번 더 들린다.

음량은 **목소리를 먼저 정규화**하고(피크 0.89 목표, 24배 상한) 그 위에서 멜로디
비율을 잡는다. 절대 RMS에 비례시키면 작게 녹음한 날 멜로디가 하한에 붙는다.
진단 칩의 `증폭 24.0배`는 상한에 걸렸다는 뜻이니 더 크게 말하면 좋다. 멜로디 음량은
결과 화면 버튼으로 네 단계 조절한다.

**멜로디 음량 하한은 목소리 피크에 연동한다.** 고정 하한을 쓰면 조용히 말한 녹음에서
멜로디가 목소리보다 커져 목소리가 아예 사라진다(실측: 멜로디가 3.3배). 마스터도 1로
클램프하지 않는다 — 천장에 여유가 있으면 비율을 유지한 채 전체를 올린다.

**이어서 녹음**하면 앞 목소리 뒤에 0.25초 무음을 두고 붙인 뒤 **전체를 다시 분석**한다.
경계를 오프셋만 옮겨 합치면 이음매 음절이 두 규칙으로 갈라지고, 슬라이서 임계값이
최대 프레임 기준이라 붙인 뒤의 값이 달라진다. 시드는 유지해 앞부분 멜로디가 그대로
남는다(곡이 길어지는 것으로 들린다). 총 120초까지.

조용하게 말한 음절은 **20ms 프레임 단위로 최대 9dB 끌어올린다**(`src/leveler.js`).
어절 끝음절이나 조사는 처음보다 10~20dB 작고, 마이크의 자동 게인은 초 단위로만
움직여 그 격차를 못 잡는다. 피크를 올리지 않으므로 멜로디 음량과는 무관하다.

멜로디 악기는 사인파가 아니라 배음을 얹은 파형이다. 순수 사인파는 진폭이 같아도
작게 들린다 — 에너지가 화자 음높이대(200~400Hz)에 몰려 있고 **귀가 가장 민감한
1~3kHz가 비기 때문**이다. 같은 게인에서 그 대역 에너지가 사인파의 54배다(실측).
총 RMS는 오히려 낮아진다(0.36 → 0.24) — 피크 정규화가 에너지를 배음으로 옮기기
때문이고, 그래서 **음량 판단을 총 RMS로 하면 개선이 반대로 보인다.**

## 소리를 만드는 방식

음절을 목표 음정으로 옮길 때 재생 속도를 바꾸면 길이가 함께 바뀌고, 음절 안의
억양이 그대로 남아 멜로디가 되지 않는다. 그래서 피치 주기마다 마크를 찍고 그
마크 중심의 창을 목표 주기 간격으로 겹쳐 더한다(TD-PSOLA, `src/psola.js`).
파형이 살아남으니 단어가 들리고 음정은 고정된다.

음절은 자연 속도로 읽고 남는 길이만 끝부분을 왕복해 채운다 — 음 길이에 맞춰
균일하게 늘리면 자음→모음 전이가 함께 늘어나 말이 뭉개진다.

마크를 못 찍은 음절은 `src/synth.js`의 그레인 루프로 떨어진다 — 음정은 맞지만
짧은 조각의 반복이라 정상상태 톤이 되므로 폴백일 때만 쓴다.

재생은 Web Audio로 직접 하지 않는다. 곡 전체를 오프라인 렌더해 WAV Blob으로
만들고 `<audio>`로 재생한다 — 아이폰에서 Web Audio 출력은 음소거 스위치·오디오
세션 상태에 묶여 "다시 듣기가 안 되는데 내려받은 WAV는 들리는" 증상이 나왔다.
덤으로 들리는 소리와 저장 파일이 같은 바이트다.

## 테스트

```bash
node --test
```

`node --test test/`처럼 **디렉터리 인자를 주면 안 된다** — Node 25에서 가짜 실패
1건과 발견 테스트 0개로 끝난다.

순수 모듈(`devsample`·`slicer`·`pitch`·`psola`·`composer`·`exporter`)과 `synth`의
순수 부분(`renderVoices`·`attackSamples`·`progressAt`)을 자동 테스트한다.
`recorder`·`ui`와 `synth`의 오디오 그래프 조립은 위 개발 경로로 확인한다.

## 브라우저 지원

Chrome·Edge에서 전 기능. Firefox는 Web Speech API를 지원하지 않아 가사 표시만 빠지고 노래는 정상 동작한다.
Safari는 `webkitSpeechRecognition`을 지원하지만 `continuous` 모드에 알려진 문제가 있어 받아쓰기가 불안정할 수 있다 — 노래 생성은 오디오만 쓰므로 영향받지 않는다.
