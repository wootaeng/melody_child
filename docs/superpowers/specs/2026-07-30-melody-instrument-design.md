# 멜로디 악기 — 피아노 위주로 바꾸고 골라 들을 수 있게 한다

작성일: 2026-07-30

8차 실기(아이폰, `?mode=chant&debug=1`) 판정에 대응한다. 지적은 셋이었다.

1. "비프음만 나오는 멜로디가 별로다" → 멜로디를 피아노 위주로, 악기를 바꿀 수 있게
2. "말이 살짝 끊긴다"
3. "멜로디 소리가 더 컸으면 좋겠다"

## 실기 진단 — 칩 숫자가 원인을 특정했다

| 칩 | 값 | 읽는 법 |
|---|---|---|
| midi | **51~55** | 155~196Hz. 멜로디가 목소리와 같은 대역에서 울린다 |
| 기준 | 154Hz | 화자 기본음 — 위 음역과 겹친다 |
| 목소리 / 정렬 | **7.3초 → 7.8초** | 늘어난 0.5초가 조각 뒤 침묵으로 들어갔다 |
| 멜로디 | 0.23 | 상한(1.0) 미도달 — 비율에 여유가 있다 |
| 증폭 | 1.0배 | 녹음은 충분히 컸다. "작다"는 녹음 탓이 아니다 |
| 격자 | 313ms | 정상(120~400ms 안). 6차의 690ms 결함은 해결됐다 |

**지적 ①·③은 같은 원인이다.** 현재 멜로디 악기의 배음은 6배음까지(`synth.js:121` `MELODY_HARMONICS`)이므로, midi 51~55에서 최고 성분이 933~1176Hz에 그친다. **귀가 가장 민감한 1~3kHz가 여전히 빈다.** 위키에 "사인파 대비 1~3kHz 에너지 54배"로 기록된 7차 개선은 더 높은 픽스처 음에서 측정한 것이고, 실제 녹음의 이 음역에서는 대부분 무효였다. 거기에 목소리 기본음(154Hz)과 같은 대역이라 마스킹까지 받는다. 저음역 정적 배음 합 + 얕은 감쇠(0.75배)는 오르간·신디사이저의 정의에 가깝다 — 그게 "비프음"으로 들리는 소리다.

**지적 ②는 원인이 둘이다.** 침묵만이 아니었다.

- `alignToBeats`가 자연 간격을 격자로 **반올림**한다(`synth.js:230`). 올라간 조각마다 `배정 − 재료`만큼 침묵이 생긴다 — 실측 총 0.5초, 조각당 평균 42ms.
- `scheduleVoiceChunk`가 조각마다 20ms 페이드 인·아웃을 건다(`synth.js:277`). 그런데 조각 중 다수는 **원본에서 연속이고 배치도 연속**이다. 그 이음매의 페이드는 아무 이유 없이 진폭을 0까지 떨어뜨렸다 올린다. 페이드 아웃 20 + 침묵 42 + 페이드 인 20 = **82ms 동안 소리가 죽는다.**

## 왜 A(감산 합성)인가

샘플 파일 없이 Web Audio로 악기를 만드는 방법은 셋이고, A를 택했다.

- **A. 감산 합성** — 배음 풍부한 파형 하나 + 음별 저역통과 필터 엔벨로프. 피아노다움의 핵심(*고배음이 기본음보다 먼저 죽는다*)을 필터 하나로 얻는다. 프리셋이 순수 데이터가 되어 `node --test`로 불변식을 검증할 수 있고, 음당 노드 3개(osc·filter·gain)다.
- **B. 가산 합성** — 배음마다 오실레이터. 비조화성까지 재현되어 가장 진짜에 가깝지만, 음당 노드가 배음 수 × 2이고 무엇보다 **프리셋 하나를 귀로 맞출 때 손댈 숫자가 8배로 늘어난다.** 악기 4개를 청취로 토닝하는 이번 작업에서 비용이 이득을 넘는다.
- **C. 샘플 내장** — 가장 진짜 소리. **나중 후보로 남긴다**(아래 별도 절).

## 프리셋 4개

`src/instruments.js` — 새 파일, 브라우저 API를 모르는 순수 데이터. `slicer`·`pitch`·`composer`와 같은 경계다.

| 이름 | 레이블 | octave | 성격 |
|---|---|---|---|
| `piano` | 피아노 | +1 | 기본값. 뾰족한 어택, 긴 감쇠 |
| `orgel` | 오르골 | +2 | 벨 — 4배음 강조, 아주 빠른 감쇠 |
| `marimba` | 마림바 | +1 | 나무 타악 — 4배음, 가장 빠른 감쇠 |
| `synth` | 신디 | 0 | **지금 소리 보존** — 필터 엔벨로프 없음 |

필드:

```js
{
  label,        // 화면 버튼 텍스트
  octave,       // 음역 오프셋(옥타브). 렌더 때만 적용 — melody.notes의 midi는 건드리지 않는다
  harmonics,    // [DC, 기본음, 2배음, …] createPeriodicWave의 imag 배열
  attackSec,    // 어택 시간
  holdShare,    // 감쇠 시작 시점(음 길이 대비). 신디는 0.6 = 현재 동작
  sustain,      // 감쇠 목표(level 대비 배율)
  filterFrom,   // 저역통과 시작 차단 주파수
  filterTo,     // 감쇠 후 차단 주파수. 생략하면 고정 필터(엔벨로프 없음)
  level,        // 악기별 음량 배율
}
```

초기값(귀로 맞출 값이다 — 실기 청취로 조정한다):

| 필드 | piano | orgel | marimba | synth |
|---|---|---|---|---|
| octave | 1 | 2 | 1 | 0 |
| harmonics(기본음 이후) | 0.6·0.4·0.28·0.2·0.14·0.1·0.07·0.05 | 0.3·0.15·0.5·0.1·0.2 | 0.2·0.1·0.45·0.08·0.05 | 0.75·0.55·0.38·0.24·0.14 |
| attackSec | 0.004 | 0.002 | 0.003 | 0.02 |
| holdShare | 0.02 | 0.01 | 0.01 | 0.6 |
| sustain | 0.35 | 0.08 | 0.05 | 0.75 |
| filterFrom | 6000 | 8000 | 5000 | 3500 |
| filterTo | 900 | 2500 | 1200 | (없음) |
| level | 1.2 | 1.0 | 1.1 | 1.0 |

`synth`의 harmonics는 현재 `MELODY_HARMONICS`와 같고 `filterTo`가 없으며 `holdShare`가 0.6이다 — **현재 소리가 그대로 재현되어야 한다.** 이게 A/B의 기준선이다.

알 수 없는 이름이 들어오면 조용히 무시하지 않고 `piano`로 떨어진다.

## `src/synth.js` 변경

**`scheduleMelody(ctx, dest, melody, startTime, level, preset, tone)`** — 지금의 `tone` 자리에 프리셋이 들어간다.

- 멜로디 전체가 공유하던 lowpass(`synth.js:136`)를 없애고 **음별 필터**로 내린다. 필터 엔벨로프가 음마다 따로 걸려야 하기 때문이다.
- 주파수는 `midiToHz(note.midi + preset.octave * 12)`. **`melody.notes`의 midi 값 자체는 바꾸지 않는다** — 화면 구슬 높이가 그 값을 쓰므로 함께 움직이면 안 된다.
- `PeriodicWave`는 프리셋당 한 번 만들어 모든 음이 공유한다(음마다 만들면 낭비다).
- `noteTimes` 반환은 그대로 — 구슬 점등이 이 시각을 쓴다.

**`createMelodyVoice(ctx, dest, { wave, preset, hz, when, durSec, level })`** — 새 함수. osc + filter + gain 한 벌을 만든다.

이 함수가 **샘플 교체 지점**이다(C로 갈 때 여기만 `AudioBufferSourceNode` 버전으로 바뀐다). 지금 샘플용 필드를 미리 만들지는 않는다 — 쓰지 않을 구조는 그 자체가 부채다.

엔벨로프:

```
gain:   0 → level*preset.level (attackSec, linear)
             → 유지 (durSec * holdShare)
             → level*preset.level*sustain (durSec * 0.9, exponential)
             → 0 (durSec, linear)
filter: filterFrom → filterTo (durSec * 0.5, exponential)   // filterTo가 있을 때만
```

`exponentialRampToValueAtTime`은 0에 도달할 수 없으므로 마지막 0은 linear로 간다 — 현재 코드와 같은 패턴이다.

`tone`은 모든 프리셋의 배음 세기 배율로 남긴다(기본 1, 0이면 순수 사인파). `?tone=`을 쓰던 기존 URL이 계속 동작하고, 실기에서 어느 악기든 배음만 조절할 수 있다.

## 말 끊김 — 연속 조각 병합 + 내림 편향

> **9차에서 ①(병합)을 철회했다. 아래 절은 그 결정의 기록으로 남기고, 대체 설계는 "말 끊김 (2) — 이음매 크로스페이드"에 있다.** 철회 근거를 함께 읽지 않으면 다음 사람이 같은 함정을 다시 판다.

**① `mergeContiguous(placed)`가 연속 조각을 병합한다.** 인접 조각 `i`, `i+1`에 대해

- `at[i] + dur[i] === at[i+1]` (배치가 이어진다)
- `from[i] + dur[i] === from[i+1]` (원본에서도 이어진다)

둘이 모두 성립하면 하나로 합친다. 합친 결과는 **원본과 비트 단위로 같은 파형**이므로 소리가 달라질 여지가 없다. 병합 후 페이드는 **실제로 침묵이 있는 자리에만** 남는다 — 쉼 자리라 원래 안전한 곳이다.

**병합은 `alignToBeats` 안에 넣지 않고 별도 함수로 둔다.** 기존 테스트들이 `placed[1].at - placed[0].at`, `placed[3].units`처럼 **인덱스로** 조각을 참조하는데 병합은 배열 길이를 바꾸므로, 안에서 합치면 테스트 4개가 깨진다. 관심사도 갈린다 — 배치 결정과 스케줄 최적화는 별개다.

**② 반올림을 내림 쪽으로 편향한다.** `Math.round(spans[i] / gridSec)` → `Math.floor(spans[i] / gridSec + GRID_ROUND_BIAS)`, `GRID_ROUND_BIAS = 0.25`.

안전한 이유: `units`의 하한에 `Math.ceil(syllableSec / gridSec)`이 이미 있다. 배정 칸이 줄어도 **음절 자체는 절대 잘리지 않고**, 줄어드는 것은 음절 뒤의 쉼뿐이다.

**침묵과 재료 건너뛰기는 같은 반올림 오차의 두 방향이다.** 총량은 보존되므로 어디로 보낼지만 고를 수 있고, 침묵은 소리가 사라지는 반면 건너뛰기는 쉼만 짧게 한다. 그래서 편향이 의미를 갖는다. 대가로 **정렬 총 길이가 자연 발화보다 짧아진다**(구현 후 픽스처 실측 5.15초 → 4.69초, 9%). 격자 이탈이 커지면 `GRID_ROUND_BIAS`를 0.5로 되돌리면 된다.

`scheduleVoiceChunk`와 `FADE_SEC = 0.02`는 그대로 둔다 — 병합이 불필요한 페이드를 제거하므로 페이드 값을 건드릴 이유가 없어진다.

## 말 끊김 (2) — 이음매 크로스페이드 (9차, ①을 대체한다)

**①과 ②가 서로를 무력화하고 있었다.** 내림 편향은 `allotted < spans[i]`를 흔하게 만들고, 그러면 `dur = min(spans[i], allotted)`가 재료를 건너뛰어 **원본에서 불연속**이 된다. 병합 조건 `from[i] + dur[i] === from[i+1]`이 깨지므로 출력에서 조각이 붙어 있어도(`at` 조건은 참) 페이드 아웃 20 + 페이드 인 20ms가 그대로 남아 **침묵이 0초인 자리에서도 진폭이 0까지 떨어진다.**

실측(48kHz, 픽스처 4종 × 96/108/120bpm):

| 지표 | 실측 |
|---|---|
| 출력 연속 경계의 이웃 게인 합 최소 | **0.000** (완전 무음) |
| 경계 40ms 창 RMS | 원본 대비 **-4.8dB** |
| 병합이 실제로 일어난 시나리오 | **12개 중 1개** |
| `dur - FADE < syllableSec`인 조각(음절 6개@120) | **5/6** — 페이드가 음절 꼬리를 직접 먹는다 |

**반증 1: `GRID_ROUND_BIAS`를 0.5로 되돌려도 병합은 살아나지 않는다.**

| 픽스처/bpm | bias 0.25 | bias 0.5 |
|---|---|---|
| 음절6개@96 | 6→6, 침묵 0ms | **6→6**, 침묵 125ms |
| 어절5덩이@96 | 5→5, 침묵 37ms | **5→5**, 침묵 **288ms** |
| 어절5덩이@120 | 5→5, 침묵 50ms | **5→5**, 침묵 250ms |

격자가 자연 간격과 **소수점까지** 같아지는 일이 실제 녹음에서 없기 때문이다. 되돌리면 침묵만 8배로 늘고 병합은 그대로 죽어 있다 — 순손실이다. 그래서 `GRID_ROUND_BIAS = 0.25`를 유지한다.

**반증 2: 기존 병합 테스트는 실기 동작을 증명하지 않았다.** `CONTIGUOUS` 픽스처 + `beatSec 0.6` → 격자 정확히 0.300 = 음절 간격. **격자와 간격이 같아지도록 만든 칼날 픽스처**였고, 그래서 실기에서 죽어 있는 함수가 초록으로 통과했다. 이번 버그가 조용히 들어온 경로가 이것이다.

**대체 설계 — 뒤 조각이 바로 이어질 때만 재료를 더 읽는다:**

> `joinsNext`(뒤 조각이 고원 끝에 올라온다): `readSec = dur + fade`, 고원 끝 = `dur`.
> 그렇지 않으면: `readSec = dur`, 고원 끝 = `dur - fade` (페이드 아웃이 자기 재료 안에서).

- `joinsNext`에서 두 램프가 **상보**가 되어 합이 1로 유지되고, 원본에서도 이어지는 경계라면 두 조각이 **같은 샘플**을 읽어 `x(1-a) + x·a = x` — 병합이 사려던 무손실 이음매를 조건 없이 산다.

**처음에는 조건 없이 `dur + fade`를 읽게 만들었고, 그것이 새 결함이었다**(리뷰에서 잡혔다). 배정 칸이 재료보다 길면 `dur = spans[i]`이므로 더 읽는 20ms가 **다음 음절의 머리**인데, 다음 조각은 침묵만큼 뒤에 시작한다. 그래서 그 머리가 최대 250ms 앞당겨 거의 풀 게인으로 한 번 더 들렸다 — 말을 더듬는 소리다.

실측(임펄스 표식을 음절 시작 +5ms에 두고 목소리 성분만 렌더): 조건 없이 읽던 버전은 표식이 제자리(게인 0.0002)보다 **256ms 이르게 게인 0.98로** 나타났다. 조건을 붙인 뒤에는 앞당긴 사본이 사라졌다.

대가는 `joinsNext`가 아닌 조각의 페이드 아웃이 재료 안으로 들어오는 것이다. 그 마지막 20ms가 음절 뒤 쉼이면 무해하고, 쉼이 그보다 짧으면 부족분만큼(최대 20ms) 꼬리가 감쇠한다 — 앞당긴 복제보다는 낫다는 판단이고, 테스트가 그 부족분이 정확히 쉼의 부족분과 같음을 단정한다.

`chunkTiming(dur, fadeSec, joinsNext)`이 `readSec = plateauSec + fadeSec` 불변식을 한 곳에 두고, `alignToBeats`의 `totalSec`이 마지막 조각의 꼬리를 포함한다(**이 값을 네 곳이 읽는다** — `buildChantGraph`, `songSeconds`, `ui.js`의 음 개수 결정과 진단 칩. 스케줄러에서 `+fade`하면 나머지 셋이 조용히 20ms 틀린다). `FADE_SEC` → `XFADE_SEC`로 개명하고 선언을 `alignToBeats` 앞으로 올렸다. `align=false`(통째로) 경로는 `joinsNext = false`가 곧 예전의 특수 처리라 분기가 하나 줄었다.

**크로스페이드가 없애는 것은 출력이 이어지는 경계의 딥뿐이다.** 배정 칸이 재료보다 긴 자리(실측 51개 경계 중 15개)는 삽입 침묵이고 거기서 소리가 없는 것은 정상이다 — 그 개수와 최대 빈틈을 테스트가 드러내 회귀를 감시한다. 그 침묵이 10차 판정 "여전히 뚝뚝 끊긴다"의 정체였고, 아래에서 다룬다.

## 말 끊김 (3) — "음절 불가침"이 침묵의 최대 공급원이었다 (10차)

10차 판정: "멜로디는 좋아졌다. 그런데 음량을 조금 줄이거나 조절 버튼이 있으면 좋겠다. **여전히 말이 뚝뚝 끊긴다.**"

계측으로 원인을 특정했다. `units`의 하한 `Math.ceil(syllableSec / gridSec)`은 음절을 자르지 않으려고 있는데, **음절이 격자보다 8%만 길어도 두 칸을 먹고 재료가 없는 나머지가 전부 무음이 된다.**

실측(픽스처 5종 × 96/108/120bpm, 침묵 = 배정 칸 − 재료):

| | 평균 침묵 | 최대 단일 침묵 | 어디서 |
|---|---|---|---|
| 10차 이전 | 189ms | **256ms** | 무음 없이 이어 말함 @108 (1.45초 발화가 2.22초로) |
| 격자 상한 400 → 200ms | 57ms | 117ms | 같은 자리 |
| + 잘림 허용 80ms | **16ms** | **33ms** | 문장 7조각 @108 |

**실제 녹음이 최악 케이스다** — 음절 사이에 무음이 없어 슬라이서가 어절 덩이를 잡고, 그 덩이가 격자보다 조금 길다.

두 수정을 함께 넣었다.

- **`GRID_MAX_SEC` 400 → 200ms.** 격자가 굵으면 `ceil` 하한의 초과분도 굵다. 잘게 하면 배정이 재료에 가까워진다(256 → 117ms).
- **`SYLLABLE_TRIM_MAX = 80ms`.** 하한을 `ceil(max(0, 음절 − 80ms) / 격자)`로 바꿔 **음절 끝 80ms까지 잘리는 것을 허용한다**(117 → 33ms).

**"음절 불가침"은 9차까지의 원칙이었고 이번에 바꿨다.** 그 원칙이 지키려던 것은 "말이 뭉개지지 않는 것"인데, 정작 그 원칙을 지키는 장치가 256ms 무음을 만들어 **더 크게 말을 끊고 있었다.** 잘리는 곳은 음절 끝 감쇠부이고 뒤 조각과 크로스페이드로 이어지므로, 50ms 감쇠부가 사라지는 것보다 256ms 무음이 나쁘다고 판단했다. 실측 잘림은 15개 배치 중 7개에서 최대 50ms다.

허용치를 URL 손잡이로 빼지 않았다 — `alignToBeats`를 부르는 네 곳에 같은 값을 넘겨야 하고 그 제약은 `totalSec` 하나로 이미 무겁다. 실기 비교군으로는 `?align=0`(정렬 자체를 끔 → 침묵도 잘림도 0)이 더 확실하고, `trimSec` 인자는 테스트가 예전 원칙(0)을 검증하는 데 쓴다.

## 멜로디 음량 버튼 (10차)

`?mel=`은 있었지만 폰에서 주소를 고쳐야 했다. 악기 버튼과 **같은 규칙**으로 화면에 낸다: 곡은 그대로 두고(`refreshMelody`를 부르지 않는다 — 곡이 바뀌면 A/B가 깨진다) 렌더 결과만 버리고 바로 재생한다.

단계는 `ui.js`의 `MELODY_LEVELS`(아주 작게 1.2 / 작게 1.8 / 보통 2.4 / 크게 3.2)이고 "보통"이 `MELODY_TO_VOICE`를 참조해 값을 두 곳에 적지 않는다. 기본을 3 → **2.4**로 내렸다(10차 "조금 줄였으면"). 발화 구간에서 멜로디 대 목소리가 +2.4dB → **+0.5dB**가 된다.

`?mel=`로 단계에 없는 값을 주면 **아무 버튼도 눌리지 않는다** — 임의의 버튼을 눌린 것으로 표시하면 화면이 거짓말을 한다.

**선형 램프를 쓴다.** 등전력(√)은 무상관 구간 전력을 평탄하게 만드는 대신 원본이 이어지는 경계에서 합을 +3dB 밀어올려 "정확히 원본"을 깨뜨린다. `psola.js`의 `xfade`도 선형이라 리포 안에서 일관된다.

**브라우저 실측에서 찾은 한 샘플 구멍:** `AudioParam`은 **첫 automation 이벤트 이전 구간에 intrinsic value(기본 1)를 쓴다.** `when`이 정수 샘플에 떨어지면 `setValueAtTime(0, when)`이 한 샘플 늦게 잡혀 그 샘플이 게인 1로 새고, 조각이 겹치는 이음매에서 합이 **2.0**이 된다(헤드리스 Chrome, 0.55초). `gain.gain.value = 0`을 먼저 넣어 막는다 — 소스가 첫 이벤트와 같은 시각에 시작하므로 원리적으로는 도달할 수 없는 경로이고, 서브샘플 반올림이 다를 수 있는 Safari가 실제 대상 브라우저라 값싼 보험으로 남긴다.

**검증 방법(프로덕션 경로):** 부호만 반대인 두 입력은 rms·peak가 같아 `mixLevels`가 같은 값을 낸다 → 두 렌더의 차 / 2 = 목소리 경로(게인 합 × voiceGain × master)이고 **멜로디가 상쇄된다.** DC를 입력으로 주면 출력이 곧 게인 곡선이므로 실제 `scheduleVoiceChunk`를 통과한 합을 잴 수 있다(node 테스트의 게인 곡선 복제와 달리 갈라질 여지가 없다). 실측: 이음매 게인비 **새 방식 1.00 / 예전 방식 0.00**.

측정 함정 셋(전부 겪었다): ⑴ 슬라이서는 무음 없이 이어 말한 구간을 **한 조각으로 묶어** 이음매를 만들지 못한다 → `bounds`를 직접 주입해야 한다. ⑵ `joinsNext` 경계는 `배정 = 재료`일 때만 생기므로 격자에 맞는 픽스처가 필요하다(음절 0.25 + 쉼 0.0625 = 96bpm 8분음표 0.3125). ⑶ 표식 임펄스를 음절 **머리**에 두면 페이드 인이 0으로 죽인다 → +5ms에 둔다.

## 명료도 — 목소리 게인 라이드 (9차)

멜로디를 건드리는 모든 수단이 8차 지적("멜로디가 작다")과 **제로섬**이다.

- 레벨을 내리면 그대로 후퇴다. 실효 차이는 애초에 크지 않다 — 멜로디/목소리 실효 RMS 비는 **+1.5dB**뿐이고(피아노 한 음 실측 `rms/melodyLevel = 0.396`), 발화 구간만 보면 거의 0dB다.
- 대역으로 비켜 갈 수도 없다. 피아노(octave+1, f0 311Hz)의 A가중 에너지는 **기본음+2배음 56% / 3~9배음 44%**인데 뒤쪽이 곧 음성 포먼트(F2·F3)다 — 차단을 내리면 지각 음량의 44%를 버려 "비프음"으로 돌아가고, 옥타브를 올리면 F1 대신 F2를 덮는다.
- **조각 기반 사이드체인 덕킹도 안 된다.** 정렬된 조각은 발화 구간이 아니라 **타임라인의 분할**이라 시간의 **99.2%를 덮는다**(PHRASES 실측 4.650/4.688초). 조각 단위 덕은 곡 전체를 누르는 것과 같아 `MELODY_TO_VOICE`를 절반으로 내린 것과 구별되지 않는다. `bounds` 기반으로 바꿔도 duty 83%에 음 온셋 83%가 덕 안에 떨어진다.

남는 비제로섬 이동은 하나다: **목소리를, 안 들리는 그 구간에서만, 크게 만든다.** 그 구간이 존재하는 근거는 두 가지다. 슬라이서 임계값이 `peak × 0.2` = **-14dB**이라 그보다 조용한 어절 끝음절·조사·무성 자음은 **애초에 `bounds`에 잡히지 않고**(조각 꼬리 안에서 재생되지만 어떤 음절에도 속하지 않는다 — 그래서 처방이 음절 단위가 아니라 **프레임 단위**여야 한다), 녹음의 `autoGainControl`은 초 단위로 움직여 녹음 전체 레벨만 맞추고 음절 간 격차는 남긴다.

`src/leveler.js`(순수 모듈)의 `ridePlan` 단계 — 각 단계가 곧 불변식이다:

1. 20ms 프레임 RMS(슬라이서와 같은 hop — 두 모듈이 같은 프레임을 봐야 "잡힌 것/못 잡힌 것"을 같은 기준으로 말할 수 있다)
2. `refDb` = 유성 프레임 90분위(최대 프레임을 쓰면 마이크를 탁 친 한 프레임이 기준을 정한다 — 슬라이서가 `RETRY_FACTORS`로 우회한 실패)
3. 부족분 `(refDb - 10dB) - frameDb`, 기준 -32dB 아래는 잡음으로 보고 건드리지 않는다
4. **피크 상한** `globalPeak / max(framePeak_{i-1..i+1})` — 창을 ±1프레임으로 잡으면 프레임 간 보간 결과도 전체 피크를 넘지 못한다(산술로 보장)
5. 상한 9dB
6. **콘 침식 2패스**(기울기 120dB/s) — 값을 내리기만 하므로 4번을 깨지 않고, 후진 패스가 공짜 룩어헤드를 준다(오프라인이라 미래를 안다). 양 끝은 가상 0dB에서 출발해 구간 경계의 계단을 막는다

`DynamicsCompressorNode`를 쓰지 않는 이유: 스펙이 니 커브를 "단조증가 함수"로만 규정해 makeup이 **구현 정의**이고(MDN 오독으로 데인 detune/playbackRate와 같은 부류), 고정 룩어헤드 지연이 붙고, 목소리 피크 불변식을 깨 `mixLevels`의 클리핑 방어가 무효가 되며, `node --test`로 검증할 수 없다.

**순서가 계약이다: 균형은 원본에서 잰다.** 라이드된 샘플로 `mixLevels`를 부르면 rms가 올라가 `melodyLevel`이 함께 커진다 — 목적과 정반대다. 그래서 멜로디 레벨·마스터·프리셋은 라이드와 무관하게 결정되고, "멜로디가 작다"로 후퇴할 경로가 구조적으로 없다.

실측: 어절 4개를 0/-6/-15/-24dB로 말한 픽스처에서 평균 부스트 **+6.3dB**, 동적 범위 **24 → 15dB**, 렌더 피크는 라이드 유무와 **동일**(0.9561).

## 클리핑 — `melodyLevel`은 피크가 아니었다 (9차)

`mixLevels`는 멜로디 피크를 `melodyLevel`로 가정했지만 실제 피크는 프리셋이 더 키운다. `0.97 × (0.89 + Fm)/(0.89 + m) > 1`이 클리핑 조건이고 실기 관측 `melodyLevel`은 0.23~0.73 — **사실상 항상** 최악 피크가 1을 넘어 `exporter.js`의 ±1 클램프에 걸렸다. 헤드리스 Chrome 렌더 실측: **수정 전 피크 1.0662(클리핑).**

`mixLevels(samples, from, length, ratio, melodyPeakFactor = 1)`의 5번째 인자로 넘기고 `master` 계산에만 쓴다(기본 1이라 기존 테스트가 그대로 통과한다).

**첫 수정의 `1.024`는 부족했다.** biquad Q=1의 공진 몫은 배음이 차단 주파수에 어떻게 앉는지에 달려 **음이 올라갈수록 커진다** — 한 음(f0 311Hz = midi 51)에서 잰 값을 상수로 쓴 것이 실수였고, 리뷰 실측에서 높은 음이 든 절이 여전히 클리핑했다(렌더 피크 1.022~1.030).

오프라인 렌더로 잰 `실제 피크 / (melodyLevel × preset.level)`의 악기별 최댓값(midi 48~72): **piano 1.255 · orgel 1.240 · marimba 1.242 · synth 1.166**. 전부를 덮는 `PRESET_RESONANCE = 1.26`을 쓴다. 검증은 여러 음역(`referenceHz` 150/300/600 → 울리는 midi 60~93)·악기·녹음 레벨 18개 구성 렌더로 했다: **최악 피크 0.9308, 클리핑 0건.**

테스트는 실측 표를 **하드코딩**해 비교한다 — `PRESET_RESONANCE`를 참조하면 상수를 바꿀 때 기대값이 함께 움직여 아무것도 검증하지 않는다(첫 버전의 클리핑 테스트가 정확히 그랬다: `master` 공식을 재구성해 항등적으로 0.97이 나와 어떤 입력에도 실패할 수 없었다). 대가로 절대 음량이 약 1.3dB 준다.

**이 사고의 뿌리는 이름이다.** `MELODY_TO_VOICE`는 RMS 비가 아니라 **엔벨로프 피크 비**이고, 실효 RMS로 가는 계수의 절반은 `createMelodyVoice`의 엔벨로프·필터(-3.9dB)에서 나온다 — "level"이라는 이름이 없어서 레벨 결정지로 세어지지 않는다. 9차 진단이 +5.4dB로 출발해 실제 +1.5dB를 잘못 읽은 것이 이 때문이다. `mixLevels` 주석에 단위를 명시하고, `test/instruments.test.mjs`에 **프리셋 실효 음량 밴드**(`level × 정규화 RMS`가 네 악기에서 ±25%)를 넣어 배음표만 고쳐 음량이 튀는 변경을 잡는다.

## 음량

- 악기 교체가 주된 개선이다. 피아노 어택은 광대역이고 +1옥타브로 6배음이 1.9~2.4kHz에 들어간다.
- 프리셋 `level`로 악기별 음량을 맞춘다(피아노 1.2).
- `MELODY_TO_VOICE = 3`과 `?mel=`은 그대로 둬 실기에서 미세조정한다.

**측정은 1~3kHz 대역 에너지로 한다.** 총 RMS는 배음이 늘면 오히려 떨어져 개선이 반대로 보인다(위키에 기록된 이 계열의 반복 함정).

## 화면과 URL

`index.html` 결과 화면에서 파형(`.voice-strip`) 다음, 버튼 그리드(`.actions`) 앞에 악기 줄을 넣는다 — "악기 고르고 → 다시 듣기" 순서가 되는 자리다.

```html
<fieldset id="instruments" class="picker">
  <legend>멜로디 악기</legend>
</fieldset>
```

버튼은 `ui.js`가 `INSTRUMENTS`로 생성한다 — 프리셋을 추가하면 화면에 자동으로 나타나고 이름을 두 곳에 적지 않는다. 선택 상태는 `aria-pressed`.

**색은 코랄(`--voice`)을 쓰지 않는다.** 이 화면의 원칙이 "코랄은 목소리에만 — 가장 뜨거운 색이 곧 아이 목소리"이므로 선택 표시는 청록 잉크(`--ink`)로 한다.

동작:

- **악기를 바꿔도 멜로디는 그대로 유지한다.** `refreshMelody()`는 곡을 새로 작곡하므로(`ui.js:207`) 호출하지 않는다. `dropSong()`만 불러 렌더 결과만 버린다. 같은 곡·같은 녹음·악기만 다른 소리를 들어야 A/B가 성립한다.
- **탭하면 바로 재생한다.** 재생 중이던 것을 멈추고 새 악기로 렌더해 즉시 들려준다. 렌더는 기존 오프라인 → WAV → `<audio>` 경로를 그대로 쓴다.
- URL `?inst=orgel`로 기본값을 지정한다.
- `?debug=1` 칩에 현재 악기와 **실제 울리는 음역**(`midi + octave*12`)을 추가한다 — 폰에서 어느 악기의 어느 음역을 듣고 있는지 읽을 수 있어야 한다.

**기본 모드를 `chant`로 바꾼다.** 사용자가 챈트 방향을 택했는데도 기본이 `full`이어서, 최근 여섯 커밋의 개선을 들으려면 주소에 `?mode=chant`를 붙여야 했다. 음정 이동은 `?mode=full`로 계속 들을 수 있어 없어지는 기능은 없다. 부수 효과로 `renderVoices`가 기본 경로에서 불리지 않아 분석·할당이 줄어든다.

## 테스트 전략

**node에서 되는 것과 브라우저에서만 되는 것의 경계를 먼저 긋는다.** `scheduleMelody`는 `AudioContext`를 받고 node에는 `OfflineAudioContext`가 없으므로 대역 에너지 실측은 원리상 node에서 안 된다. 이 경계를 흐리면 "테스트는 통과하는데 소리는 안 바뀌는" 상태가 된다.

**`node --test` (순수):**

- `instruments.js` 불변식 — 모든 프리셋에 필수 필드가 있다 / `filterTo`가 있으면 `filterFrom`보다 작다(고배음이 먼저 죽는 방향) / 감쇠 길이 순서가 marimba < orgel < piano < synth / 알 수 없는 이름은 `piano`로 떨어진다 / `synth`의 배음과 holdShare가 현재 값과 같다(기준선 보존)
- `mergeContiguous` — **출력 샘플 → 원본 샘플 매핑이 병합 전과 완전히 같아야 한다.** "최대 차이 0"보다 강한 단정이고, 어느 시각에 원본의 어디가 들리는지를 직접 비교하므로 부동소수 경계 문제도 드러난다. 호출자의 배열을 변형하지 않는 것도 함께 못 박는다.
- 삽입 침묵 총량 ≤ 자연 길이의 2% / **정렬이 자연보다 길어지지 않는다**(길어진 만큼이 곧 침묵이다) + 압축 하한 80%(쉼이 통째로 사라지면 말이 뭉친다) / 음절 불가침·비겹침(기존 테스트 유지)
- **병합이 실제로 일어난다** — 연속 조각이 있는 픽스처에서 조각 수가 줄어드는 것을 확인한다. 이게 없으면 병합 코드가 죽어 있어도 통과한다.

**브라우저 실측 (구현 후):**

- 1~3kHz 대역 에너지를 **피아노 vs 신디로 A/B**. 두 악기가 이 지표에서 갈리지 않으면 개선을 악기에 귀속할 수 없다 — 위키의 반박 리뷰가 못 박은 규칙이다.
- 실제 울리는 주파수가 `midi + octave*12`와 일치하는지.

**뮤테이션 확인:** 병합을 끄면 조각 수 테스트가, 내림 편향을 되돌리면 침묵 총량 테스트가, `filterTo > filterFrom`으로 바꾸면 프리셋 불변식이 각각 빨강이 되는지 본다. 이 절차 없이는 "통과할 수밖에 없는 단정"을 구분할 수 없다.

**픽스처 주의:** 정렬·병합 테스트에는 말소리 성질(발화 20% + 쉼 80%, 파고율 ~4.5)을 가진 픽스처를 쓴다. 순음 계열로는 이 계열 결함이 가려지는 것이 이 프로젝트에서 이미 두 번 재현됐다.

## 측정 결과 (구현 후 실측)

실기와 같은 낮은 기준음(midi 51 = 155Hz)에서 **목소리를 무음으로 두고 멜로디만** 렌더해 측정했다 — 반주가 섞이면 측정이 오염된다는 것이 이 프로젝트에서 이미 겪은 함정이다.

| 지표 | 결과 | 어디서 |
|---|---|---|
| **1~3kHz 에너지 피아노/신디** | **55배** (1.47e-07 / 2.68e-09) | 헤드리스 Chrome |
| 같은 지표 마림바 / 오르골 | 45배 / 24배 | 헤드리스 Chrome |
| 실제 울리는 음 | 4악기 모두 `expected === measured` (311·622·311·156Hz) | 헤드리스 Chrome |
| 저역 100~500Hz (목소리와 겹치는 대역) | 오르골 4.1e-10 — 사실상 비었다 | 헤드리스 Chrome |
| 총 RMS | 피아노 0.0307 **<** 신디 0.0324 | 헤드리스 Chrome |
| `?tone=0` (순수 사인파 보존) | 1~3kHz 1.8e-14 | 헤드리스 Chrome |
| 삽입 침묵 총량 | 288ms(5.6%) → **37ms(0.7%)** | node |
| 정렬 / 자연 길이 | 1.031 → **0.911** | node |
| 병합 후 조각 수 | 3 → **1** | node |
| 병합 안전성 | 출력 → 원본 샘플 매핑이 완전히 동일 | node |

**총 RMS가 반대로 나온 것을 다시 확인했다** — 피아노는 신디보다 총 RMS가 낮은데 1~3kHz는 55배다. 이 계열에서 총 RMS를 지표로 쓰면 개선을 퇴보로 읽는다.

측정 방법(재현용): 리포 루트에 임시 측정 페이지를 두고 `python -m http.server`로 서빙한 뒤 헤드리스 Chrome으로 연다. **`--dump-dom`은 쓸 수 없다** — 비동기 렌더가 끝나기 전에 덤프한다. 결과는 `fetch('/__result?' + encodeURIComponent(json))`로 보내 **서버 접근 로그에서 읽는다.**

## 나중 후보 — C(샘플 내장)

라이선스는 걸림돌이 아니다. 단 **"비상업이라 괜찮다"는 근거가 아니다** — 저작권은 상업·비상업을 구분하지 않고, 공개 리포 + GitHub Pages는 재배포다. **CC0/퍼블릭 도메인으로 확인된 소스**를 쓰면 되고, CC BY라면 README에 귀속 한 줄을 넣으면 된다. NC 라이선스 샘플을 "비상업이니 됐다"고 집어 들면 그때는 실제 위반이다.

용량도 문제가 아니다 — 단음 mp3가 20~50KB이니 옥타브당 2~3음 + 리샘플로 200~400KB다.

C의 진짜 비용은 **비동기 초기화**다. 채택 시 필요한 것:

- CC0 또는 퍼블릭 도메인이 확인된 단음 소스
- `decodeAudioData` 비동기 초기화
- **로드 실패 시 A 프리셋으로 폴백** — 정적 페이지에서 네트워크 실패는 정상 경로다
- 옥타브당 2~3음 + `playbackRate` 리샘플
- `createMelodyVoice`만 교체. 프리셋의 `octave`·`level`·엔벨로프는 그대로 쓴다

**A를 먼저 하는 이유**: A에서 확정한 프리셋 테이블이 그대로 샘플의 명세가 된다. 음역·음량 균형을 청취로 정해 두면 샘플을 끼울 때 그 값을 그대로 쓸 수 있다.

## 대가와 한계

- **정적 파형 + 필터로는 진짜 피아노가 되지 않는다.** 실제 피아노는 배음이 비조화이고 어택에 타현 노이즈가 있다. "피아노 같은 느낌"까지가 A의 상한이고, 그 이상은 C가 필요하다.
- **내림 편향은 격자 이탈량을 늘린다.** 5차 실기에서 15ms였던 값이 커진다 — 정렬의 목적 자체를 해치지 않는지 측정으로 확인해야 한다. 이탈이 커지면 편향 계수(0.25)를 낮춘다.
- **음역을 올리면 멜로디가 목소리와 덜 어울릴 수 있다.** 마스킹은 풀리지만 "따로 노는" 인상이 생길 수 있어 실기 판정이 필요하다. `octave`가 프리셋 데이터라 조정은 한 줄이다.
- **병합은 원본의 결함을 그대로 통과시킨다.** 원본에 이미 클릭이 있으면 페이드가 없어진 자리에서 들린다. 병합 조건이 "원본에서 연속"이므로 새 불연속은 생기지 않지만, 원래 있던 것은 남는다.
