## C1. 옥타브 정규화 부재 — 목소리가 목소리로 들리지 않는다

`composeMelody`의 으뜸음은 MIDI 60~64(262~330Hz)로 고정이고, `synth`는 `rate = 목표Hz / f0`로 조각을 이동시킨다. 화자의 f0가 그보다 낮으면 재생 속도가 그만큼 올라간다. 실측(시드 1~30 × 24음):

| 화자 | rate 최소 | 중앙값 | 최대 | 2배 초과 |
|---|---|---|---|---|
| 아이 280Hz | 0.93 | 1.40 | 3.74 | 19% |
| 여성 200Hz | 1.31 | 1.96 | 5.23 | 45% |
| **남성 120Hz** | **2.18** | **3.27** | **8.72** | **100%** |

부모 목소리로는 전부 2배 이상 빨라져 "자기 목소리로 부른 노래"라는 전제가 무너진다. 게다가 rate가 높으면 재생 가능 길이가 짧아져 거의 항상 루프 분기로 떨어지고(초당 수십 회 반복) 인공적인 톤이 된다.

**조각별로 옥타브를 접지 않는다** — 음마다 옥타브가 무작위로 튀어 멜로디 윤곽이 사라진다. **곡 전체를 한 번 이조**한다. 적용 후 남성 120Hz 중앙값 1.63배, 윤곽은 그대로.

`src/composer.js` — `composeMelody`에 세 번째 인자를 추가한다. 이조는 `makePhrase` **이전**에 해야 프레이즈가 이조된 으뜸음을 쓴다. `rnd()` 호출 순서는 바뀌지 않으므로 기존 결정성 테스트가 그대로 성립한다.

```js
export function composeMelody(noteCount, seed, referenceHz) {
  if (!Number.isInteger(noteCount) || noteCount < 1) {
    throw new RangeError(`noteCount는 1 이상의 정수여야 한다: ${noteCount}`);
  }
  const rnd = mulberry32(seed);
  let tonicMidi = 60 + Math.floor(rnd() * 5); // C4~E4
  const bpm = 96 + Math.floor(rnd() * 25); // 96~120

  // 화자의 음높이에 맞춰 곡 전체를 옥타브 단위로 옮긴다. 조각마다 따로 접으면
  // 음의 옥타브가 무작위로 튀어 멜로디 윤곽이 사라지므로 전곡을 한 번만 옮긴다.
  // 화음도 tonicMidi에서 파생되므로 반주가 함께 따라온다.
  if (referenceHz > 0) {
    tonicMidi += 12 * Math.round(Math.log2(referenceHz / midiToHz(tonicMidi)));
  }

  const makePhrase = () =>
    Array.from({ length: PHRASE_LEN }, () => ({
      midi:
        tonicMidi +
        PENTATONIC[Math.floor(rnd() * PENTATONIC.length)] +
        (rnd() < 0.2 ? 12 : 0),
      beats: rnd() < 0.25 ? 0.5 : 1,
    }));

  const verse = Array.from({ length: VERSE_LEN / PHRASE_LEN }, makePhrase).flat();
  const notes = Array.from({ length: noteCount }, (_, i) => ({ ...verse[i % VERSE_LEN] }));

  notes[notes.length - 1] = {
    midi: tonicMidi,
    beats: Math.max(1, notes[notes.length - 1].beats),
  };

  return {
    notes,
    bpm,
    tonicMidi,
    verseLen: VERSE_LEN,
    verseCount: Math.ceil(noteCount / VERSE_LEN),
  };
}
```

`test/composer.test.mjs`에 추가:

```js
test('referenceHz를 주면 곡 전체를 옥타브 단위로 이조한다', () => {
```

## I2. 절대시각 0 스케줄 — 재생 경로에서만 어긋난다

`buildGraph`는 `when = 0`에서 스케줄을 시작한다. `OfflineAudioContext`는 `currentTime`이 0이라 정확하지만, `AudioContext`는 다르다. 실측:

```
resume() 직전 currentTime = 0
resume() 직후 currentTime = 0
30ms 뒤      currentTime = 1.01
```

오디오 스레드가 실제로 돌기 시작할 때 시계가 **1초가량 앞으로 점프**한다. 그 전에 스케줄하면 곡 앞 1초가 과거에 걸려 첫 음의 페이드인이 건너뛰어지고(클릭음) 앞 음들이 뭉친다. 스펙이 명시한 "재생과 렌더가 같은 소리"가 재생 쪽에서 깨진다.

`src/synth.js` — `buildGraph`가 시작 시각을 받고, 시계가 움직인 뒤의 안전한 시작 시각을 구하는 헬퍼를 export한다.

```js
// resume 직후 currentTime이 0에 머물다가 오디오 스레드가 돌기 시작할 때 크게 앞으로
// 점프한다(실측 약 1초). 점프 전에 스케줄하면 곡 앞부분이 과거에 걸려 첫 음이 뭉친다.
export async function safeStartTime(ctx, lead = 0.1) {
  await ctx.resume();
  if (ctx.currentTime === 0) {
    await new Promise((resolve) => {
      const tick = () => (ctx.currentTime > 0 ? resolve() : requestAnimationFrame(tick));
      tick();
    });
  }
  return ctx.currentTime + lead;
}
```

`buildGraph`는 세 번째 인자 `startTime = 0`을 받아 `when`의 시작점으로 쓰고, `scheduleAccompaniment`에도 넘긴다. 반환값에 `master`를 추가한다(아래 I6에서 재생 중단에 쓴다).

```js
export function buildGraph(ctx, { audioBuffer, segments, f0s, melody, chords }, startTime = 0) {
  if (segments.length !== melody.notes.length) {
    throw new RangeError(
      `segments(${segments.length})와 notes(${melody.notes.length}) 개수가 다르다 — 호출 전에 정규화할 것`,
    );
  }

  const secPerBeat = 60 / melody.bpm;

  const master = ctx.createGain();
  master.gain.value = 0.9;
  master.connect(ctx.destination);

  const voiceBus = ctx.createGain();
  voiceBus.gain.value = 1;
  voiceBus.connect(master);

  const accompBus = ctx.createGain();
  accompBus.gain.value = ACCOMP_GAIN;
  accompBus.connect(master);

  let when = startTime;
  melody.notes.forEach((note, i) => {
    const f0 = f0s[i];
    // f0가 null인 조각(무성 자음)은 음정 이동을 포기하고 원음 그대로 — 리듬만 맞춘다
    const rate = f0 ? midiToHz(note.midi) / f0 : 1;
    const noteSec = note.beats * secPerBeat;
    scheduleSegment(ctx, voiceBus, audioBuffer, segments[i], rate, when, noteSec);
    when += noteSec;
  });

  scheduleAccompaniment(ctx, accompBus, melody, chords, secPerBeat, startTime);

  return { durationSec: when - startTime + TAIL_SEC, master };
}
```

`scheduleAccompaniment`는 시그니처 끝에 `startTime`을 받아 두 군데에 더한다:

```js
function scheduleAccompaniment(ctx, dest, melody, chords, secPerBeat, startTime) {
  for (const chord of chords) {
    const when = startTime + chord.startBeat * secPerBeat;
    ...
  }
  ...
  for (let beat = 0; beat < totalBeats; beat += 0.5) {
    const when = startTime + beat * secPerBeat;
    ...
  }
}
```

`renderOffline`은 `buildGraph(ctx, spec)`을 그대로 호출한다(startTime 기본값 0).

## I6 + I2 후속. 재생마다 새 컨텍스트를 만들지 않는다

`stopPlayback`이 `close()`의 프로미스를 버려, 연타하면 정리되지 않은 컨텍스트가 쌓인다. 브라우저의 동시 AudioContext 상한(Chrome 6개)에 닿으면 `new AudioContext()`가 던진다.

`src/ui.js` — 컨텍스트 하나를 만들어 재사용하고, 중단은 `master`를 끊는 방식으로 한다. 이미 예약된 소스는 끊긴 뒤 소리가 나지 않고 끝나면 수거된다.

```js
let audioCtx = null;
let playingMaster = null;
let playToken = 0;

function stopPlayback() {
  if (playingMaster) {
    playingMaster.disconnect();
    playingMaster = null;
  }
}

async function play() {
  const token = ++playToken;
  stopPlayback();
  const current = session;
  if (!current) return;

  if (!audioCtx) audioCtx = new AudioContext();
  const startTime = await safeStartTime(audioCtx);
  // await 사이에 다시 녹음·연타가 끼어들면 이 재생은 이미 무효다
  if (token !== playToken || session !== current) return;

  const { master } = buildGraph(
    audioCtx,
    {
      audioBuffer: current.audioBuffer,
      segments: current.segments,
      f0s: current.f0s,
      melody: current.melody,
      chords: current.chords,
    },
    startTime,
  );
  playingMaster = master;
}
```

## I4. `composeMelody`를 세 곳에서 따로 호출하지 않는다

`play`·`save`·`showResult`가 각자 `composeMelody(session.segments.length, seed)`를 계산한다. 지금은 PRNG가 결정적이라 일치하지만, 정확성이 "세 호출의 인자가 계속 같기를" 기대하는 구조에 걸려 있다. C1의 `referenceHz`가 붙는 순간 인자를 네 곳에 흩뿌려야 하고, 하나 빠뜨리면 재생과 저장이 다른 옥타브로 갈린다.

`src/ui.js` — 멜로디를 `session`에 저장하고 시드가 바뀔 때만 다시 만든다.

```js
function medianF0(f0s) {
  const voiced = f0s.filter((f) => f !== null).sort((a, b) => a - b);
  return voiced.length ? voiced[Math.floor(voiced.length / 2)] : null;
}

// 멜로디는 한 곳에서만 만든다. 재생·저장·안내 문구가 같은 곡을 봐야 한다.
function refreshMelody() {
  session.melody = composeMelody(session.segments.length, seed, session.referenceHz);
  session.chords = chordsFor(session.melody);
}
```

`analyze()`는 반환 객체에 `referenceHz: medianF0(f0s)`를 추가한다. `session`을 설정한 직후(`finishSession`과 `loadDevSample` 양쪽)와 `remix` 핸들러의 `seed += 1` 직후에 `refreshMelody()`를 호출한다.

`save()`는 `session.melody`/`session.chords`를 쓰고, `showResult()`는 `session.melody.verseCount`를 읽는다 — 어느 쪽도 `composeMelody`를 직접 부르지 않는다.

## I1. `녹음 시작` 이중 클릭 → 마이크 스트림 영구 누수

`startSession()`은 `await startRecording(...)`이 끝난 뒤에 화면을 바꾼다. 그 사이 버튼은 계속 눌린다. 두 번 누르면 `handle`이 덮여 첫 번째의 스트림·컨텍스트·rAF 루프를 아무도 정리하지 못한다 — **세션이 끝나도 마이크 표시등이 켜져 있다.** 첫 클릭의 30초 타이머도 살아남아 두 번째 녹음을 일찍 끊는다.

`src/ui.js` — `startSession` 진입 시 버튼을 잠그고, 성공·실패 양쪽에서 푼다.

```js
async function startSession() {
  setNotice('');
  el('start').disabled = true;
  try {
    handle = await startRecording({ ... 기존과 동일 ... });
  } catch {
    setNotice('마이크를 쓸 수 없어요. 브라우저에서 마이크를 허용해 주세요.');
    show('idle');
    return;
  } finally {
    el('start').disabled = false;
  }
  ...
}
```

## I3. 음성인식이 네트워크 오류에서 무한 재시작한다

`onerror`가 모든 오류를 무시하고 `onend`가 무조건 재시작하므로, 오프라인이나 권한 거부 상태에서는 30초 내내 오류→재시작 스핀이 돈다. Chrome의 인식기는 원격 서비스를 쓰므로 정적 호스팅 + 네트워크 단절이면 바로 이 상태가 된다. 게다가 사용자는 아무 설명 없이 가사가 안 나오는 화면을 본다.

`src/recorder.js`:

```js
// 재시도해도 결과가 같은 오류들. 여기서 포기하지 않으면 30초 내내 스핀이 돈다.
const FATAL_SPEECH_ERRORS = new Set(['network', 'not-allowed', 'service-not-allowed']);
const MAX_RESTARTS = 10;
```

`startTranscription(onTranscript, onUnavailable)`으로 인자를 하나 늘리고:

```js
  let restarts = 0;

  recognition.onerror = (event) => {
    if (FATAL_SPEECH_ERRORS.has(event.error)) {
      state.done = true;
      onUnavailable();
    }
  };

  recognition.onend = () => {
    state.committed = joined();
    state.current = '';
    if (state.done || restarts >= MAX_RESTARTS) return;
    restarts += 1;
    try {
      recognition.start(); // 침묵으로 끊긴 것 — 다시 듣는다
    } catch {
      /* 이미 시작된 경우 무시 */
    }
  };
```

`startRecording`은 옵션에 `onTranscriptUnavailable = () => {}`를 받아 `startTranscription`에 넘긴다.

`src/ui.js`의 `startSession`은 그 콜백에서 경고를 노출한다:

```js
      onTranscriptUnavailable: () => {
        el('stt-warning').hidden = false;
      },
```

## 감수하고 넘어가는 항목 (최종 리뷰 트리아지 결과)

- `devsample`의 `sampleRate = 48000` 기본값은 호출자 전부가 명시적으로 넘겨서 실제로 쓰이지 않는다 — 테스트 공백이 아니라 죽은 인자. 지금은 그대로 둔다.
- `slicer`의 마지막 부분 홉(≤20ms) 버림, 비배수 버퍼 길이: `end = frameCount * hop ≤ samples.length`라 범위 초과가 구조적으로 불가능.
- `pitch`의 백색소음 `null` 판정이 통계적인 점: 실패 시 결과가 `rate = 1`(원음)이라 실패 방향이 안전하다.
- `composer`의 8의 배수 경계: 코드 추적상 결함 없음, 커버리지 공백일 뿐.
- `URL.revokeObjectURL` 즉시 호출, 캔버스 CSS 스케일: 지원 대상(Chrome·Edge)에서 동작하며 후자는 미용 문제.
- **AGC·노이즈 억제와 분할 임계값의 상호작용은 테스트로 잡을 수 없다** — 조용한 방/시끄러운 방에서 사람이 각각 한 번 녹음해 봐야 한다.
